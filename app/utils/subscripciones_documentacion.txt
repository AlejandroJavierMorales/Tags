📘 MÓDULO DE SUSCRIPCIONES — DOCUMENTACIÓN TÉCNICA
🧭 1. Propósito del módulo

El módulo de suscripciones gestiona:

Clientes (businesses)
Planes disponibles
Suscripción activa por cliente
Renovaciones (manuales actualmente)
Control de vigencia (fechas de inicio y expiración)
🗄️ 2. MODELO DE BASE DE DATOS
🏢 2.1 tags_businesses

Representa el cliente.

Campos:
id (PK)
name
email
phone
created_at
updated_at
Relación:
1 business → N subscriptions
📦 2.2 tags_plans

Catálogo de planes disponibles.

Campos:
id (PK)
name
code
price
currency

👉 Es una tabla estática (configuración del sistema).

🔁 2.3 tags_subscriptions

Entidad central del sistema.

Campos:
id (PK)
business_id (FK → tags_businesses)
plan_id (FK → tags_plans)
status (active | inactive)
payment_provider (ej: manual, futuro mercadopago)
amount
currency
duration_months
started_at
expires_at
created_at
updated_at
🧠 Regla principal

Cada business puede tener múltiples suscripciones, pero SOLO una activa.

🔌 3. APIs DEL MÓDULO
📌 3.1 Crear cliente
Endpoint:
POST /api/business/create
Input:
{
  "name": "",
  "email": "",
  "phone": "",
  "plan_id": "",
  "start_date": "",
  "duration_months": 1
}
Proceso:
Insert en tags_businesses
Obtener plan
Calcular fechas:
started_at
expires_at
Insert en tags_subscriptions con status active
📌 3.2 Actualizar cliente
Endpoint:
POST /api/business/update
Input:
{
  "id": "",
  "name": "",
  "email": "",
  "phone": "",
  "plan_id": "",
  "start_date": "",
  "duration_months": 1
}
Proceso:
Update tags_businesses
Cerrar suscripción activa:
status = 'inactive'
Crear nueva suscripción active
📌 3.3 Listar clientes
Endpoint:
GET /api/business/list
Proceso SQL:
JOIN business + subscription activa
JOIN plan
LEFT JOIN QR codes
GROUP BY business.id
Retorna:
datos del cliente
plan activo
estado de suscripción
métricas QR
📌 3.4 Eliminar cliente
Endpoint:
DELETE /api/business/delete
Proceso:
elimina business
(dependencias futuras: subscriptions y QR)
🔁 4. FLUJO DE SUSCRIPCIONES
➕ CREACIÓN
Business creado
    ↓
Plan seleccionado
    ↓
Se calcula duración
    ↓
Se crea subscription (ACTIVE)
✏️ ACTUALIZACIÓN
Business update
    ↓
Se desactiva subscription actual
    ↓
Se crea nueva subscription ACTIVE
🔄 ESTADO ACTUAL

Siempre existe:

1 subscription ACTIVE
N subscription INACTIVE (histórico implícito)
⏳ 5. REGLAS DE FECHAS
Cálculo base:
startedAt = start_date || now
expiresAt = startedAt + duration_months
Formato UI:
Backend: ISO string
Frontend: dd/mm/yyyy
📊 6. REGLAS DE NEGOCIO
6.1 Suscripción activa
status = 'active'

Solo una por business.

6.2 Suscripción vencida

Se determina por:

expiresAt < now
6.3 Próxima a vencer
diffDays <= 15
